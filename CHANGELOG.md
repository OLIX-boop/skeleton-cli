## [0.4.0]

### Added

- Documents: PDF, Word (`.docx`), PowerPoint (`.pptx`), Excel (`.xlsx`), OpenDocument (`.odt`, `.ods`, `.odp`),
  EPUB, RTF and e-mail (`.eml`) are converted to Markdown, locally and without API keys. Packing a directory
  includes them (`--no-documents` or config `documents: false` leaves them out); skeleton mode keeps headings and
  the first sentences of each section, outline mode only the headings with section sizes.
- PDFs are read with PDFium (WebAssembly): headings from font sizes, paragraphs, tables, code blocks and
  hyphenated words are rebuilt; running headers, footers and page numbers dropped. Pages without a text layer
  (handwriting such as OneNote exports, scans, drawings) are detected, rendered as grayscale images cropped to
  their content, and can be transcribed once: transcriptions are saved in `.astpack/transcripts/`, keyed by the
  document's content, and replace the images from then on.
- `astpack doc <files...>`: documents as Markdown, whole or by `--section` / `--pages`, as `--outline` or
  `--skeleton`; `--images <dir>` saves the pages that need looking at as PNGs. HTML is converted here too.
- MCP tools `read_document` (small documents whole, long ones as an outline; images of pages to look at) and
  `save_transcription`. `skeleton_file` returns condensed text for documents. The plugin's Read hook suggests
  `read_document` the first time Claude reads a document.
- Data files outside full mode: CSV and TSV keep the header and 20 rows, JSON Lines 5 records, large JSON its
  shape (long arrays and maps shortened), SVG images a one-line description.


### Added

- Claude Code plugin (`/plugin marketplace add OLIX-boop/skeleton-cli`, then `/plugin install astpack@astpack`).
  It bundles the MCP server, a skill describing when skeletons beat reading files, and a once-per-file Read hint
  for large source files. An eval suite checks that Claude uses astpack on cold starts and API lookups, and not
  for small edits.
- MCP: server instructions say when to use astpack; `path` is optional and defaults to the project root;
  `skeleton_file` takes `paths` for up to 20 files at once.

### Fixed

- MCP: `pack_codebase` and `skeleton_file` also return the document in `structuredContent`. Clients that show
  the model only structured content, such as Claude Code, used to get the token counts without the code.

## [0.2.0]

### Added

- `--query <text>` (config `query`, MCP `query`): focus the files most relevant to a task description, ranked
  by BM25 over identifiers and paths; the summary lists the matches. `--query-limit` caps them (default 5).
- MCP `pack_codebase` and `estimate_tokens` accept `query`, `queryLimit`, `related` and `order`.
- C# and Swift: bodies inside `#elif`/`#else` branches are now stripped too (one parse per branch index).
- Minified files are replaced by a one-line note, and generated sources (`DO NOT EDIT`, `@generated`,
  `AUTOGENERATED` headers) are outlined, in skeleton mode. On VS Code this outlines 825 generated protocol
  files and drops 30 minified ones.
- Jupyter notebooks (`.ipynb`) are packed as percent-format scripts: outputs dropped, magics commented out,
  code cells skeletonized (Python, Julia, Scala, TypeScript and JavaScript kernels). `.ipynb_checkpoints` is
  ignored by default.
- `--order stable` (config `order`): least recently changed files first and the diff last, so re-packs share
  a long prefix with the previous pack and hit LLM prompt caches; `--order size` sorts smallest first.
- Six new languages: Zig, Solidity, Haskell, OCaml (`.ml`, `.mli`), Julia and Objective-C, with outlines and
  import resolution for `--deps` / `--related`.
- Worker threads for transforms and token counts on projects with 200+ files (`ASTPACK_WORKERS` to tune or
  disable): packing VS Code without a cache drops from ~135 s to ~55 s on 4 cores.
- On-disk cache of transforms and token counts per project (`astpack cache`, `astpack cache clear`,
  `--no-cache`, `ASTPACK_CACHE_DIR`, `ASTPACK_NO_CACHE`): re-packing VS Code drops from ~130 s to ~11 s.
- `--related [depth]` (config `related`, MCP `related`): also include in full the files within `depth` import
  hops of a focused file, in either direction. A token budget compresses them after every other file.

## [0.1.0]

First release.

### Added

- Skeleton mode: Tree-sitter body stripping for TypeScript, JavaScript (incl. JSX/TSX), Python, Go, Rust, Java,
  C#, C, C++, Ruby, PHP, Kotlin, Swift, Scala, Dart, Elixir, Bash and Lua, using current upstream grammars, plus `<script>` blocks in Vue, Svelte
  and Astro files. Output re-parses cleanly and is idempotent.
- Focus mode (`--focus`) and raw mode (`--full`); unsupported files are included up to a line/character limit.
- File discovery honouring nested `.gitignore`, the enclosing repository's rules, `.git/info/exclude`,
  `.packignore`/`.astpackignore`, `--ignore` and `--include`, with built-in excludes for dependencies,
  lockfiles, binaries, build output and likely secrets.
- Markdown, XML and JSON output; `--stdout`, `--clipboard`, `--instructions`, `--no-tree`.
- Token analytics for `cl100k_base` and `o200k_base`, savings versus raw source, and per-model input cost;
  `--claude-tokens` for exact Claude counts via Anthropic's token-counting API.
- `--outline` repo-map mode (also a budget step), `--comments all|docs|none`, `--max-tokens` budgets, `--split-tokens` part files, `--deps` import graph.
- Git integration: `--changed`, `--diff`, `--remote`.
- Presets (`--preset review|explain|refactor|debug`) with ready-made instructions.
- Secret redaction (on by default, `--no-redact`).
- `astpack.config.json` / `.astpackrc` with a JSON Schema, `astpack init`.
- `astpack mcp`, a Model Context Protocol server with `pack_codebase`, `estimate_tokens` and `skeleton_file`.
- `--dry-run`, `--stats-json` and `--watch`; transforms and token counts are cached in memory, so repeated
  MCP calls and watch rebuilds only redo changed files.
- `astpack tree` token map per directory, and an `extensions` config option for custom file types.
- A GitHub Action (`action.yml`) with token outputs and a job summary.
- Programmatic API (`pack`, `render`, `skeletonize`, `fitToBudget`, `computeStats`, …).
